# ICM: read → draft → check → correct, one change at a time

Claim: The working loop is read the named sources, draft to a known location, check the draft against the source (decisions, owners, dates, unknowns kept visible), then correct by pointing at the specific instruction or source sentence; fix one cause, rerun the same task, keep the change only if it helps. Build the system after the first useful result, never before.

Evidence: Mistakes 1–7 in 3.3: entry file contains everything; routing implicit; tree bigger than the work; personality instead of task; stale context; one undifferentiated pile; system built before the first useful result. Repair example: "We will send the proposal Friday" vs source "Timing to confirm" → add the rule "do not turn a suggestion into an approved commitment" → rerun → keep if it improves → check another example before calling it reusable. 4.4: "Start with one recurring mistake… write the instruction that would help with that actual problem."

Elaboration:
- Unknowns are useful: "Owner: not stated" tells you what needs a follow-up instead of becoming a commitment.
- Decide before deliverable (4.3): a decision brief with goal, constraints, open questions and "what I will check before using it."
- Two fresh practice copies, same task, change only the instruction file — one run is a check, not proof.

Why it matters here: this is backpass's loop done by hand (transcripts → evidence-backed proposal → apply → observe), and the reason the first migration step is one routing table and one area, not the whole tree.
