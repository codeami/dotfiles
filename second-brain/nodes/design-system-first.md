# Design system first

Claim: Establish a design system before building screens, so later components and screens don't reinvent elements and stay consistent.

Evidence: "once the design system is established, later on we can build more UI components and more screens and change how things work without having to reinvent every single element."

Elaboration:
- Claude design creates the system (icons, colors, components) from the PRD, then screens from it.
- A design system is the "factory" half of ICM's configure-the-factory-not-the-product principle.
- The exported archive becomes the spec the frontend crewmate builds against.
